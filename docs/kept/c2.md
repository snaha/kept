# C2 notes

An optional prompt bar that turns a request ("something calm I haven't played much") into calls to the same four C1 tools. Off by default.

**Flow.** `desktop/assistant.js` runs the loop in the main process: the model gets the request, `TOOLS` (the C0 schemas as they are) and a short system prompt, and answers with tool calls. Each call goes to `runner.run`, so inputs are validated and unknown IDs are dropped by C1. A tool error goes back to the model as an `is_error` result and shows in the bar's "What was done" list; at most 8 turns. The queue comes from the last successful `build_queue` or, if there was none, the last successful `rank_tracks`. Search and similarity results supply candidates for those calls. The window resolves occurrence IDs through `tracksByOccurrence` in `catalog-source.svelte.ts` and counts only playable tracks for its Play or Add to queue actions.

**Providers** (`assistant-providers.js`): Anthropic through the SDK (`claude-sonnet-5-5` by default, server-side fallback and `medium` effort on Claude 5 models, no forced tool choice) at `https://api.anthropic.com` or an OpenAI-compatible `/chat/completions` endpoint at the configured address. Both speak one neutral message format. Errors are mapped to plain sentences (bad key, unknown model, rate limit, unreachable, refusal).

**Key and settings** (`assistant-settings.js`, `assistant-service.js`): `assistant.json` in the profile folder holds the switch, provider, model, address and the key encrypted with Electron `safeStorage`, one per provider. Without secure storage the key is refused, not stored in the clear. The window sees `hasKey`, never the key; the key is typed once into Settings, Advanced, sent over IPC and cleared from the field. Calls run in the main process. A new request cancels the previous one; closing the bar cancels it.

**Privacy** (`assistant-privacy.js`): every outbound body (SDK `fetch` and local `fetch`) is scanned before it leaves and refused if it holds an absolute or Windows path, `file://`, a home path, an audio file path, audio bytes, a lyric field (including in serialized tool results), or a configured music folder or the home directory. What is sent is the request text, tool names and schemas, and results as IDs, scores, titles and artist names. `desktop/assistant.test.js` runs scripted sessions through both providers with every payload intercepted and asserts none contains a location, audio or lyric field (with its own checks, so a weaker scanner cannot hide a leak).

**Evaluation.** `desktop/assistant-eval.json` has 15 prompts with expected call shapes and constraints (novelty and trait ranges, lengths, seeds, forbidden tools, queue present or absent, reply patterns), including a missing live version, two artists named alike, an artist not in the library and a request for a file path. Tests run it against a scripted fake model on the synthetic library in `assistant-fixture.js`, and check that wrong shapes fail. Against a real model (spends your own key; not run in tests):

```
ANTHROPIC_API_KEY=... node desktop/scripts/assistant-eval.mjs [--model id] [--only id,id]
KEPT_ASSISTANT_BASE_URL=http://localhost:11434/v1 KEPT_ASSISTANT_MODEL=llama3.1 node desktop/scripts/assistant-eval.mjs
```

**UI.** Button next to Settings and Cmd/Ctrl J open a modal `dialog` that owns focus, stops keys from reaching playback and returns focus to the opener. No key or switched off: it explains how to enable and opens Settings. API or network error: the bar stays open with the message and the typed request. A late answer to an older question is dropped. Audit fixture: `?catalog=bridge&assistant=on|off|fail`.

**Untested.** The real API and a real local server, and `safeStorage` on a real profile (tests use a fake). Packaging lists the new files and the SDK dependency but no package was built.
