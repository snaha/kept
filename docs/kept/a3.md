# A3 notes: virtual catalog and review UI

Code: `frontend/src/lib/catalog-source.svelte.ts` (which catalog), `virtual-catalog.ts` (the bridge as a
provider), `album-review.svelte`, `activity-panel.svelte`; bridge read model and field review in
`shared/catalog-bridge.js`.

## Which catalog

The window browses the library's own catalog when `window.musicCatalog.catalogAlbums` exists, the
Settings choice is on (default on) and the library holds albums. Otherwise the Navidrome provider
serves, with the reason kept in `catalogSource.fallback`: `off`, `unavailable` (browser, LAN, older
desktop), `empty`, `catching-up` (the hash job still has files queued) or `failed` (the bridge threw).
The choice is made once per fresh load. A background refresh keeps the catalog it started with and a
failed refresh keeps the albums on screen. Playlists always come from Navidrome.

## Contracts

- Collection IDs are `album:<anchor>`; the Navidrome IDs of the same album stay as aliases, so a
  playlist play lights the same tile. Catalog IDs, occurrence IDs and queue-entry IDs stay distinct.
- Sorts map to the projection: artist, title, added. Search pages per kind with load-more; tracks of
  albums not found come back as `trackAlbums`. Search, details and browse read the same projection,
  so they agree on title, artist and track list for one anchor, also after a correction.
- Covers use the asset's Navidrome link (`al-<id>`), so nearest-the-viewport warming is unchanged.
  Stream links are registered as tracks are handed out; play and skip never ask the catalog.
  Tracks kept in history are primed in batches at load.
- Every async result carries its request generation; stale pages, searches and reviews are dropped.
  `catalog:changed` refreshes the open album in place (no scroll, focus or order change).

## Review

Album menu, "Album details & changes", shows title, artist, year and genre with provenance (set by
you, from the file tags, changed by Kept naming the route), Lock/Unlock and field Undo. A refused
write puts the control back and says why; typed text survives a background update. Activity lists
route-authored change sets with before and after per operation and undoes one operation or all.
All of it is the ledger, so it survives a restart.
