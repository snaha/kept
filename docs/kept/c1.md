# C1 notes

The four tools run with no LLM, in `shared/tool-runner.js` (`createToolRunner({ catalog, features, history })`, helpers in `shared/tool-support.js`). `runner.run(name, input)` checks the input against the C0 contract, runs the tool, drops every ID the catalog does not hold (an album must be listed, a track must be in its album's detail), counts rejected IDs and validates the output against the contract. It returns `{ name, output, dropped }`. The window calls it as `window.musicCatalog.tool({ name, input })` (catalog bridge operation `tool`, validated by `validateCatalogBridgeRequest`); the main process builds the runner with the history adapter in `desktop/tool-services.js`.

**Services.** `CatalogService` projections (`listCatalogAlbums`, `getCatalogAlbum`, `searchCatalog`, `getAsset`), read once per catalog version and refreshed per album by its version. Track index reads use bounded batches and reuse unchanged album details. `HistoryStats.albumStats()` is plays per catalog album ID (the provider IDs of the listening history mapped through the bridge). `FeatureSource` is `{ method: { id, version }, albumVectors(albumIds), trackVectors(assetIds) }`, maps of `ArrayLike<number>`; `createFakeFeatureSource` is the in-memory one. A feature store that throws is treated as empty.

**Behaviour and weights** (named constants in `tool-support.js`):

- `search_catalog`: the FTS projection, albums then tracks, filtered by favourite and trait ranges (a track takes its album's traits and must be available). An empty query lists on the same filters. The score is rank order, 1 for the first.
- `find_similar`: score = (max(0, cosine) + 0.3 if the same top-level folder) / 1.3 (`FOLDER_BONUS_WEIGHT` 0.3, B0). The folder is `source/first path segment` of the album's first track location, read inside the process and never returned. The seed's artist is excluded unless `excludeSeedArtist` is false; unavailable albums are left out. Ties go by ID. One basis per list: `sound` when the seed has a vector, else `traits` (hybrid over traits both have), else `metadata` (same folder only). With a `novelty`, score = 0.7 x similarity + 0.3 x novelty fit (`SIMILAR_WEIGHTS`); without one the history is not used. Novelty fit is `n x (1 - familiarity) + (1 - n) x familiarity`, familiarity being Dig's curve, `log2(plays + 1) / 5` capped at 1 (31 plays). Tracks: the tracks of the best albums, a track with its own vector counting half.
- `rank_tracks`: weighted mean of the parts a track has: trait fit 0.4, similarity (hybrid, track vector else album vector) 0.4, novelty 0.2 (`RANK_WEIGHTS`), renormalised over the parts present; no parts is 0.5. Ties keep the caller's order. Ranking skips duplicates, unknown IDs and unavailable tracks.
- `build_queue`: seeds first (a track, or an album's first track), then tracks of albums with the highest mean similarity to the seeds (seed albums count 1), scored with the rank weights. At most `maxPerAlbum` (default 2) per album, no duplicates, no artist within the last 3 picks and no album within the last 5 (`ARTIST_SPACING`, `ALBUM_SPACING`), relaxed to "not twice in a row" and then to none before the queue is left short. Unavailable tracks are skipped. `run(name, input, { targetSeconds })` also stops at a duration; it is not in the contract.
