# A0 findings

Path spike, run with Navidrome 0.64.2 and the environment Kept uses in `desktop/main.js`, on `test_library` (149 of 151 files are audio) and a read-only scan of a 958-track real collection.

- With `ND_SUBSONIC_DEFAULTREPORTREALPATH=true`, `getSong`, `getAlbum` and `search3` all report the same absolute `path`: the scanned path under the combined root, for example `<profile>/music-folders/folder-<16 hex>/Artist/Album/08 - Track.mp3`. It is the symlink path, not the `realpath`. The `folder-<hex>` segment is `musicFolderLinkName(folder)` from `desktop/music-folders.js`, so the real file is the link target plus the remaining relative path. With a single uncombined folder the path is the real path.
- Without the flag, `path` is a tag-derived `Artist/Album/File` string (`[Unknown Artist]/[Unknown Album]/08 - Track.mp3`) that does not exist on disk, so the normalised relative join resolved 0 of 149. It is a last resort only, for layouts that already match the tags.
- Song IDs and reported paths were identical after a restart and a full rescan on the same data folder. IDs derive from the scanned path, so they change if the combined root moves; the profile directory and the per-folder link names are stable, so they do not change in normal use. The flag changes only the reported path, so records that hold only a song ID resolve with one `getSong` call once the flag is on.
- `desktop/track-paths.js` resolves 149 of 149 test-library songs and 958 of 958 real-collection songs through the reported path.
