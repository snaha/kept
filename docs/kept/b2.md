# B2 notes

First visible intelligence release: Dig scores an untagged library on estimated energy, and an album has a "More like this" action.

**Estimated energy** (`desktop/estimated-traits.js`). The feature worker ranks album aggregates for the current method version and keeps the result in memory until the album rows change. The catalog bridge serves it as `estimatedTraits()` (IPC `catalog:estimated-traits`, by album anchor ID). Estimates are regenerated from `features.sqlite` and kept out of the decision ledger.

- Score: the B0 heuristic unchanged (z-scores of loudness, onset rate, flux, centroid at half weight, dynamics at minus half), then the album's **percentile within this library**, 0 to 100. 50 is a typical album of this library; the scale moves as the library or analysis grows, which is why it is recomputed and never stored. With fewer than 5 analysed albums nothing is estimated. No confidence is given.
- Only energy ships (traits check 15 of 20). Acoustic and vocal stay hand-set; mood stays held.
- Window: `syncDecisions` fills `catalog.estimated[id].energy` for an album only when it has no hand value, so `AlbumTraits` and `DigPanel` show it dashed through the existing `estimated` path and `digScore` uses it on the energy axis (with mood on). A hand value is never replaced; `resolveTraits` shows and scores it first. If the read fails, what is shown stays.
- Refresh: on load and on each catalog change. Estimates that appear while the analyser runs show after the next such sync (no polling yet).

**More like this** (`similar-albums.svelte.ts`, `similar-lane.svelte`). Album menu, albums of the library's own catalog in the desktop app. Calls `window.musicCatalog.similarAlbums`, then resolves up to five returned IDs with `catalogAlbum`. The lane is titled "Sounds like…" and says it is based on how albums sound. Each row has Play and Add to queue. The same query reports whether the seed has sound features. With no matches, the lane shows "No similar albums are available to play right now" for an analysed seed and "Kept is still listening to this album" when the seed has no features. A newer request supersedes an older one. A failure clears the old list and shows an error.

**Sound only.** The query uses album summaries for candidate IDs, then ranks their embeddings in the feature worker. The generic `find_similar` tool still supports trait and folder fallback.

**Checks.** Desktop: `estimated-traits.test.js`, and `tool-runner.test.js` for the zero bonus. Frontend: `estimated-energy.svelte.test.ts` (estimate fills an untagged album, hand wins, failure keeps the view, lane states and supersession) and the existing `dig-scoring` tests. The audit fixture's catalog stand-in takes `?estimates=on` and `?similar=sound|listening`. Seen at 1440x900 and 390x844 against it. Not tested: a real analysed profile in the Electron app, and a library where estimates arrive during use.
