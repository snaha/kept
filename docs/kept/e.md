# E notes: Spotify playback adapter

- Off by default. Settings > Advanced has the section. The user pastes their own client ID (PKCE, no secret, loopback redirect `http://127.0.0.1:8888/callback`) and signs in. Needs Premium and a Spotify device (Connect). The Web Playback SDK is not used: it needs Widevine, which stock Electron lacks.
- `desktop/spotify.js` runs in the main process and handles PKCE sign-in, tokens encrypted with `safeStorage` (`spotify/tokens.bin`), the chosen device (`config.json`), device list, track search and the commands `play / pause / resume / seek`. The window gets a status and those commands over `musicSpotify` (preload), never a token or an API URL. Cancel and sign-out close any pending sign-in listener. Sign-out deletes the tokens and device, withdraws consent and drops in-flight responses. Kept leaves audio, artwork and the library on Spotify.
- Source: `SPOTIFY_SOURCE` in `shared/spotify-source.js`: kind `spotify`, evidence `deterministic`, licence `proprietary`, `analysisAllowed: false`, network `internet`, consent key `spotify` (new `ConsentKey`). Sign-in registers the source and records consent `granted`; sign-out records `denied`.
- `CatalogRef` kind `spotify` (id = Spotify track ID). The resolver resolves it synchronously to `{ kind: 'spotify-track', trackId }` when the ID is a plain Spotify ID. `Track.source` is `'spotify'`, `Track.id` is `spotify:track:<id>`, cover is empty. The queue and listening history retain the track reference, title, artist, album and duration after sign-out. Mixed queues replay through the resolver when signed in.
- `frontend/src/lib/spotify-adapter.ts` polls the remote position while Spotify owns playback. It reports track end, loss of device and foreign tracks. Polling normally runs once a second and waits longer when Spotify rate-limits requests or token refresh is temporarily unavailable.
- Refusals: `assertAnalysable` (`shared/source-policy.js`) is checked when a job of a class flagged `analysis: true` is queued or claimed in `LibraryWorker`. B1 must flag its analyse class and put `sourceId` in the payload. The tool runner refuses a Spotify ID as a seed or `similarTo`, never passes one to a feature store, and drops it from every result.
- Gaps: no Spotify library or playlists, only search. Playback and sign-in were not run against a real Spotify account. Not verified: Premium and allowlist errors, device handoff timing, token refresh in the wild, the connected and device-picker view of the Settings section (visual check covered the signed-out view at 1440x900 and 390x844).
