# L1 notes: authenticated LAN catalog

Code: `desktop/lan-catalog.js` (server side, wired into the web server in `desktop/main.js`),
`frontend/src/lib/lan-catalog.ts` (client), `catalog-source.svelte.ts` (choice). Tests:
`frontend/tests/lan-catalog.test.ts`.

- The page's own origin (the web port the Share link points at) serves `POST /__kept/lan/*`. No new port, no CORS.
- Desktop Share issues a catalog-only key bound to the page origin and Navidrome server. `POST session` exchanges
  that key for a random per-device token with a 12 hour expiry. The server retains only its hash, limits sign-in
  failures per address and catalog calls per token. Restart, `revokeAll()` and share password rotation revoke sessions.
- Offered: `catalog-albums`, `catalog-album`, `catalog-search`, `playback-links` through the bridge's own validators.
  Everything else (writes, tools, consent, settings, activity, review) is refused 403 before the bridge is called;
  non-POST is 405. A response holding a path-like key is refused, so only IDs and the bridge DTOs leave.
- Browsers keep the Share key with its account. Fresh album loads allow 300 ms for LAN readiness before falling
  back to Navidrome. A later fresh load can reuse the readiness result. Playlists open directly from Navidrome.
  Restored history asks the LAN client for playback links. A 401 mid-session triggers one new exchange.
  Covers and streams keep the Navidrome routes.
- Gaps: no UI to revoke devices or list them; plain HTTP like the rest of sharing; not run on a real phone;
  `sharing-integration` (real Navidrome) is unchanged.
