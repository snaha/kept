# D0 design

Visual rules, all in the zinc dark palette and Avenir Next from `DESIGN.md`:

- **Provenance.** A value the user set is solid: a filled marker and the normal slider fill. A computed value is dashed: a hollow dashed ring and a dashed range. An axis with no value is dotted and dimmed. Setting a value by hand always wins and turns that axis solid on the same frame.
- **No layout jumps.** The marker column and a reserved note line are always present, so a value changing source never moves anything. On hover or focus the note says "Set by you", "Estimated by Kept, 80% sure" or "Not set yet".
- **Dig.** The panel shows a legend of albums tagged by you and albums estimated, only while there are estimates. Scoring uses only the axes an album has.
- **Consent.** One question with two buttons, "Look up album details online" and "Stay offline", beside a plain list of what is sent. Nothing is sent until the user agrees. Settings, Advanced holds the same choice as a checkbox, off by default.
- **Activity.** A list of receipts, newest first, each with who did it, when, and an Undo button. An undone entry stays listed, struck through and marked "Undone". An entry that cannot be undone shows a disabled button.

Components in `frontend/src/lib`: `trait-marker.svelte` (`source`), `AlbumTraits.svelte` (`tile`, `estimated`), `DigPanel.svelte` (new `estimated` count), `consent-choice.svelte` (`onchoose`, `busy`), `lookup-toggle.svelte` (`value`, `onchange`), `activity-panel.svelte` (`entries`, `onundo`). Types live in `traits.ts` (`TraitReading`, `EstimatedTraits`) and `activity.ts` (`ActivityEntry`). The consent answer is kept in a device preference by `consent.svelte.ts` until a later phase stores it as a user decision. The consent step and Activity panel are not mounted yet.
