# A3f notes

- `Track.catalogRef` (`CatalogRef = { kind: 'navidrome' | 'asset'; id }`, in `shared/music.ts`) names the catalog entity. Absent means `{ kind: 'navidrome', id: rawId }`, so every legacy queue entry and history row keeps working. `Track.id` stays the occurrence identity, `rawId` the asset or Navidrome id, `queueEntryId` the live queue slot.
- `frontend/src/lib/playback-ref.ts`: `PlaybackRef = { kind: 'navidrome-stream'; songId }`, `trackCatalogRef(track)`, `createPlaybackResolver()` with synchronous `resolve / register / forget`, the shared `playbackResolver` and `resolveTrackPlayback(track)`. A Navidrome ref resolves to itself. An asset ref resolves only if the provider registered it, so play and skip never await the catalog. An unresolved ref fails like an unavailable track.
- `player.svelte.ts` resolves at play time (adapter `available` and `prepare`, the next-track warm-up and scrobbles). The queue and history never store a playback ref.
- `frontend/src/lib/virtual-catalog.ts`: `createVirtualCatalog({ resolver, playbackSourceId })` is a `CatalogProvider<CatalogService>` behind `VIRTUAL_CATALOG_ENABLED = false` and is not imported by the app. It registers each asset's playback ref from its provider track link (`playbackSourceId`, Navidrome) when it lists tracks. It has no search or playlists, and no covers.
- History: `isStoredTrack` accepts an optional, validated `catalogRef`. The schema version stays 1 and no column was added, because rows live in the context JSON. `historyTrack` rebuilds a Navidrome cover only for Navidrome refs.
- A3 must know: `listAlbums` has no ordering, so the provider yields pages in service order. Virtual albums have no cover source yet. `artistAlbums` scans all pages. A virtual asset whose Navidrome link is missing is `available: false`.
